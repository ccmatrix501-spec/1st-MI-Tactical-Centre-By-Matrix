HOW TO UPDATE THE LIVE GITHUB PAGES SITE
----------------------------------------
1. Keep your existing assets/ folder exactly as it is
   (maps, bugholes, markers, companies, mi3d GLBs, training-material, restriction-maps, icons, etc.).
   The binary assets are NOT re-included here because they are large and already in your repo.

2. Replace the previous React source (App.tsx or the equivalent entry component)
   with the new App.tsx from this folder.

3. Rebuild the web target the same way you produced the previous 1.4.6 static files
   (Vite / your normal build command that outputs the hashed JS + CSS into assets/).

4. Copy the newly generated files into the GitHub repo root / assets:
   - the new index-*.js (and any CSS it needs)
   - update index.html if your build regenerates it
   - keep / overwrite the meta files from this package (version.txt, sw.js, manifest, etc.)

5. Commit message example:
   Web build v1.4.7 – desktop source port + mobile/web guards

6. Push to origin and wait for GitHub Pages.

7. First load after deploy will clear the old service-worker cache and reload once
   (same behaviour as 1.4.6).

WHAT CHANGED IN 1.4.7
---------------------
- Full logic, cert checklists, training material, 3D builder data and styles
  taken from the latest desktop App.tsx you supplied.
- WEB_BUILD_VERSION = "1.4.7"
- isWeb detection so desktop-only APIs (steOverlay / steKeybinds / native folder picker)
  are safely skipped in the browser.
- Help text and footer now show the correct web/mobile instructions.
- All previous mobile layout, touch controls and JSON save behaviour from the 1.4.6 web
  build should continue to work once you rebuild with the same CSS / mobile adaptations
  you already had.

If your build pipeline already injects the mobile CSS and web-save polyfills,
just swapping App.tsx and rebuilding is enough.

After the new JS is live, open the site on phone and confirm the Menu → Quick Actions
(or the footer) shows “Web build v1.4.7”.
